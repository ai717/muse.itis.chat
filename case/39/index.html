用 Muse Code 一口气造 5 个应用：总共花了约 10 美元，界面漂亮但规则逻辑会翻车

花小钱实测终端编程代理的真实边界：产出速度惊人，但胜负条件、红绿灯这类规则执行不可靠。

🎯 任务背景
创作者 PromptsLove 在 Muse Code 发布当天自费实测，用它一口气做了五个应用：一个多页前端网站、益智游戏 Gridlock、3D 交通路口模拟、把提交日志变发布说明的 SaaS 工具 Shipyard，以及把手绘图转成可编辑流程图的 Python 应用，逐个打分并公开了花费。
📝 做法步骤 (5 步)
  1. 1
    在终端安装 Muse Code，在项目文件夹里运行
  2. 2
    每个应用都给详细提示词而不是一句话需求
  3. 3
    逐个实测产出：点遍界面、跑通核心流程、检查规则逻辑是否真的生效
  4. 4
    记录每类失败：Gridlock 的通关判定没触发、交通模拟里车辆和行人闯红灯
  5. 5
    统计总花费并对照其他编程模型做性价比判断
📊 产出与证据
作者实测：五个应用全部生成，总花费约 10 美元（Standard 档）；Shipyard 和手绘图数字化工具拿到 4/5 分，手绘流程图的每个分支连拼写都被正确还原；但 Gridlock 的获胜逻辑从未触发、交通模拟会违反自己设定的红绿灯规则。
💡 复现要点
提示词要把规则写成可验收的条件，交付后专门测边界逻辑（胜负、权限、状态切换），不要只看界面是否漂亮；预算敏感可考虑 Contributor 档，但要用代码参与训练来换低价。
⚠️ 踩坑提示
作者两次踩到同一个坑：模型明明理解规则，却不把规则执行到底，连最高推理档位也一样；另外视觉产出风格同质化明显，不指定品牌风格就会千篇一律。
